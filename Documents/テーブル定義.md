# テーブル定義 - mimamori

データはすべて SQLite（`modernc.org/sqlite`）で管理します。外部のデータベースサーバーは使いません。データベースは用途ごとに次の 3 種類のファイルに分かれます。

| 種類 | ファイル | 置き場所 | マイグレーション | 内容 |
| --- | --- | --- | --- | --- |
| セントラル管理用 DB | `central.db` | データディレクトリ（既定は実行ファイルと同じディレクトリの `data/`。実行ファイルの場所を求められない場合はカレントディレクトリの `data/`） | `app/migrations/central` | アカウント、セッション、確認コード、確認済みのブラウザ、トークン、監視ルール、テンプレート、抑止条件、履歴、証明書、通知、監視対象の一覧、すべての監視対象のコマンドセットの実行の指示、設定と内部の状態 |
| 監視対象ごとの DB | `targets/agent-<agents.id>.db` | データディレクトリの `targets/` | `app/migrations/agentdb` | 監視対象（トークンで特定するエージェント 1 件、または内蔵エージェント）ごとの検知、自ホストの情報、最後に保存した報告の識別子、コマンドセットの定義、実行と結果 |
| エージェントのローカル DB | `agent.db`（内蔵エージェントは `builtin-agent.db`） | データディレクトリ | `app/migrations/agentlocal` | 設定（接続先、トークン、独自 CA、インスタンス ID）、ワーカー数、適用中の監視ルール、未送信の報告、走査の状態、配信されたコマンドセットの定義、コマンドセットの実行とスケジュールの状態 |

- 日時はすべて INTEGER の Unix 秒（UTC）で保存します。`0` は「未設定」を表します。画面、CLI、通知ではローカル時間で表示します。
- ファイルは実行ユーザーの所有で、umask 077 により `0600`（ディレクトリは `0700`）で作成します。既存のファイルとディレクトリの所有者と権限は変更も確認もしません。
- スキーマは goose で管理し、DB を開いたときに未適用のマイグレーションを自動適用します。セントラルは起動時にすべての監視対象の DB を開いて適用します。各 DB に goose 管理用の `goose_db_version` テーブルが作られます（アプリケーションは DB を開くときの確認で読むだけです）。
- 最初のリリースまでは、DB の種類ごとのスキーマを 1 つのマイグレーションファイル（`0001_init.sql`）の中で変更します。このため、別のビルドが作った DB は、マイグレーションが適用済みと記録されていても列が足りないことがあります。そこで各 DB は、作成に使ったマイグレーションファイル（名前と内容。改行は LF にそろえる）の SHA-256 から求めた 0 でない 31 ビットの値（フィンガープリント）を SQLite の `user_version` に持ちます。DB を開くときは（`app/modules/db.go` の `migrate`）次のとおりです。
  - 空の DB: マイグレーションを適用し、すべてのファイルのフィンガープリントを書きます。マイグレーションはファイルごとに 1 つのトランザクションで適用し、途中のファイルで失敗した場合は、適用できたファイルのフィンガープリントを書きます（次に開いたときに残りを適用します）。
  - それ以外: 適用済みと記録されたファイルのフィンガープリントが保存されたものと一致すれば開き、後から加わったマイグレーションファイルがあれば適用して、すべてのファイルのフィンガープリントを書き直します。
  - フィンガープリントが無い、異なる、またはこのビルドに無いマイグレーションが適用済みの DB は、何も書かずに拒否します。メッセージ（コード `common.db_other_build`）は「database <ファイルのパス> was created by another build of the program and its tables do not match this build: the data directory has to be created again (move it away and set the program up anew)」です。その場合はデータディレクトリを作り直します（今のディレクトリを別の場所へ移し、改めてセットアップする。データは引き継げません）。
  - 確認と適用は、DB のファイルがあるディレクトリの排他ロック（flock）を持って行うため、同時に開いた別のプロセスが適用の途中の DB を見ることはありません。
- モデルは 1 テーブル 1 ファイルで `app/models/<テーブル名>.go` に置きます。読むだけの関数は読み取り側（`models.Reader`）を、書き込む関数（先に読むものを含む）は書き込みのトランザクション（`models.Writer`）を受け取ります。DB への接続とトランザクションは [システム仕様.md](システム仕様.md) の 6.1 を参照してください。

| exec_watermark | 以前の版が使った、実行されるファイルの走査で前回までに確認した状態の変更時刻（`exec_since` が無いときだけ読む。書き込まない） |
| exec_since | 実行されるファイルの走査で、走査の順序（パスをディレクトリ名ごとに比べた順）の区間ごとに最後に確認した時刻（JSON: `[{"from": 区間の始まりのパス（"" は先頭）, "since": Unix 秒}]`） |
| exec_root_since | 実行されるファイルの走査で、新しく見つかった書き込みを許可するパスのディレクトリに使う時刻（JSON: パス → Unix 秒）。そのディレクトリを最後までたどったら消す |
| exec_resume | 実行されるファイルの走査が項目数の上限に達したとき、次の確認で続きを始めるパス（1 巡を終えたら消す） |
| exec_pass_start | `exec_resume` がある間、その 1 巡を始めた日時 |
| writable_resume | 書き込み可能な状態の走査が項目数の上限に達したとき、次の確認で続きを始めるパス（1 巡を終えたら消す） |
| writable_pass | `writable_resume` がある間、その 1 巡を始めた日時とそれまでに見つけた書き込みを許可するパスのディレクトリ（JSON） |
| last_full_scan | 最後に書き込み可能な状態の走査を最後まで終えた 1 巡を始めた日時 |
| scan_signature | 走査の起点と書き込みを許可するパスの組（変わったら全体を走査し直す） |
| scan_prev_roots | 走査の起点か書き込みを許可するパスを変えたときに覚えておく、それまでの書き込みを許可するパスのディレクトリ（JSON。変更後の最初の 1 巡を終えたら消す） |
| dropped_pending | 保存量の上限で捨て、まだ報告していない検知の件数 |
| last_audit_event | 最後に読んだ auditd のイベントの位置（JSON: 秒、ミリ秒、通し番号） |
| command_defs | 配信されたコマンドセットの定義と署名（`modules.CommandDefinitions` の JSON） |
| workers | エージェントのワーカー数（同時に処理する単位の数）。1〜64 の整数、無ければ 1。`agent set-workers`（内蔵エージェントは `agent set-workers --builtin`）で変え、次の起動で反映する。セントラルの設定 `workers` とは別の値 |
| running_workers | 起動中のエージェントが使っているワーカー数。起動時に書き、終了時に消す（ロックを保持しているプロセスがあるときだけ読む） |

### outbox

未送信の報告。保存量に上限があり、超えると `normal` の検知から古い順に捨てます。コマンドセットの実行の報告は別に大きさの上限があります（[システム仕様.md](システム仕様.md) の 12.5.2）。自ホストの情報は最新の定期の報告の行にだけ残し、検知も捨てた件数も無く、コマンドセットの報告も無く、適用の結果が新しい報告と同じ古い行は、新しい報告を保存するときに削除します。モデル: `app/models/outbox.go`。

| カラム名 | 型 | NULL | 既定値 | 説明 |
| --- | --- | --- | --- | --- |
| id | INTEGER | NO | AUTOINCREMENT | 主キー（送信の順） |
| created_at | INTEGER | NO | - | 作成日時 |
| payload | TEXT | NO | - | 報告（`modules.ReportRequest` の JSON）。行を作るときに作った報告の識別子（`report_id`）を含み、上限で書き換えても変わらない |
| alert_count | INTEGER | NO | 0 | 含まれる `alert` の検知の件数 |
| normal_count | INTEGER | NO | 0 | 含まれる `normal` の検知の件数 |
| command_bytes | INTEGER | NO | 0 | コマンドセットの実行を含む報告の大きさ（含まない報告は 0）。合計が上限を超えたら古い順に出力を捨てる |

リレーション: なし

### scan_roots

### command_executions

エージェントが開始したコマンドセットの実行。同じ実行を 2 回行わないために使います。同期では、`request_id` が 0 より大きく終了していない行の `request_id` を、実行中の手動の指示の一覧（`running_requests`）として送ります。起動時に終了していない行は、中断された実行として報告します（実行中のコマンドが記録されていれば、そのコマンドの結果も中断として報告します）。モデル: `app/models/command_execution.go`。

| カラム名 | 型 | NULL | 既定値 | 説明 |
| --- | --- | --- | --- | --- |
| run_uid | TEXT | NO | - | 実行の一意な ID（主キー） |

| set_revision | INTEGER | NO | 0 | 実行した定義の版 |
| request_id | INTEGER | NO | 0 | 手動の実行の指示（0 より大きい値は一意。同じ指示を 2 回実行しない） |

| running_started_at | INTEGER | NO | 0 | 実行中のコマンドの開始日時（0 は実行中のコマンドなし） |
